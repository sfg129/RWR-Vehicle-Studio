# 图标渲染功能技术记录

本文记录独立黑白载具图标渲染功能的需求判断、实现过程、数据流、关键数学、文件边界、验证结果与维护约束。后续修改该功能时，应同步更新本文和对应自动化测试。

## 1. 目标与不可破坏的边界

功能目标：

- 在 `RwrVehicleStudio` 主窗口内通过标签页进入 `ICON 渲染`；
- 复用现有 `.vehicle` 合成结果、资源索引、`.weapon` 解析和 OGRE `.mesh` 读取器；
- 自动组合正常外观模型及炮塔引用的武器模型，不要求手工转换、导入和排列；
- 使用标准透视相机、单方向光、低环境光和亮度阈值生成纯黑/纯白车体；
- 背景默认为参考图实测值 `#181818`；
- 支持实时调节相机、车体/炮塔姿态、光照、阈值、留白和输出尺寸；
- 支持多个命名参数预设的保存、读取和删除；
- 支持临时调整单个 `visual` 或 `weapon` 的位置，但绝不写回 `.vehicle/.weapon`；
- 通过原生保存窗口导出 PNG。

明确隔离：

- 图标渲染器不创建乘员；
- 不创建碰撞框、外观框、护盾框、乘员位置框、入口辅助线、网格或坐标轴；
- 不加载纹理；
- 不复用编辑器的 `TransformControls`，因此导出图中不会混入三轴控件或选择框；
- 渲染预设和临时部件偏移不进入编辑器撤销栈，也不影响载具脏状态；
- 原有 `SceneController` 的透视编辑场景保持不变。

## 2. 实施记录

### 阶段 A：现有能力审计

确认已有链路可以直接使用：

1. `SourceDocument` 解析并保留 XML 源文本；
2. `composeVehicle()` 生成基础载具与当前覆盖文件的合成预览；
3. `ResourceCatalog.resolve()` 按“覆盖文件 → 主来源 → 有序次要来源”解析模型；
4. `ResourceCatalog.weapon()` 读取 `.weapon`，解析 OGRE mesh 或静态体素模型引用；
5. `parseOgreMesh()` 直接解析 OGRE 1.x 二进制 `.mesh`；
6. `turretWorldPose()` 处理 `parent_turret_index`、炮塔位置和累计 Y 轴旋转；
7. `tireVisualPosition()` 处理履带/轮组的左右实例位置。

因此没有加入 Blender、Assimp 或批量格式转换步骤。

审计时工作区已有未提交的炮塔旋转中点功能。新增实现采用新控制器和新组件，避免重写 `scene-controller.ts`、`EditorViewport.vue` 中的用户修改。

### 阶段 B：资源目录核实

用户给出的意图路径是 WW2 基础包模型目录。实际磁盘核实结果：

- 不存在：`D:\steam\steamapps\common\RunningWithRifles\media\packages\ww2\_base\models`
- 存在：`D:\steam\steamapps\common\RunningWithRifles\media\packages\ww2_base\models`
- 核实时该目录递归包含 963 个文件；
- 同包 `ww2_base\weapons` 也存在，但本次只按用户要求自动补入模型回退目录，武器目录继续使用资源配置中的主/次来源。

资源优先级必须保持：

```text
单文件覆盖
  > 模组模型主目录
  > 用户配置的其它次要模型目录
  > D:\...\packages\ww2_base\models
```

应用资源选择前通过只读命令 `directory_exists` 检查该目录；存在时由 `setWw2BaseModelFallback()` 把它追加为最后一个模型来源，不存在时从当前选择中移除。这使同一构建在非 Windows 或不同 Steam 库路径上仍可正常建立资源索引。旧版预设反序列化的兼容语义仍保持“缺失 secondaryFolders 时迁移为空数组”，避免破坏已有测试和数据格式。

### 阶段 C：独立渲染内核

新增 `IconRenderController`，独立拥有：

- `modelScene`：只放载具、环境光、方向光；
- `outputScene`：全屏二值化后处理；
- `PerspectiveCamera`：标准近大远小的透视相机；
- `WebGLRenderTarget`：带 4x MSAA 的中间目标；
- OGRE mesh、静态体素和 `BufferGeometry` 缓存；
- 部件绑定表和临时偏移表；
- 按需渲染调度，不运行永久动画循环。

### 阶段 D：界面、预设与导出

新增 `IconRenderer.vue`：

- 左栏：正常 `visual` 与 `turret weapon` 部件列表及临时 XYZ 偏移；
- 中栏：实时最终渲染结果；点击可选择部件，但不显示选择框；
- 右栏：参数预设、相机/姿态、光照/阈值、输出参数；
- 底栏：场景构建、诊断和导出状态。

新增 Rust 命令 `save_render_png`：

- 只接受原生保存对话框返回的路径；
- 自动补 `.png`，拒绝其它扩展名；
- Base64 解码后检查 8 字节 PNG 文件签名；
- 只向用户明确选择的父目录写入；
- 取消保存返回 `null`，不产生文件。

### 阶段 E：透视修正

初版使用正交相机。实物预览反馈指出它与原版图标的空间表现不符，并出现反常的远端尺度观感。渲染相机随后改为标准 `THREE.PerspectiveCamera`：

- 默认垂直视场角为 `35°`；
- 提供 `20°–65°` 可调视场并纳入参数预设；
- 近处严格大于远处，不再使用正交视锥；
- 自动构图不使用包围球近似，而是把八个包围盒角点变换到相机局部空间，逐点求满足水平/垂直视场的最小相机距离；
- 导出 1:1 图像时以方形宽高比重新求距离，完成后恢复预览宽高比。

导出构图后续修正：实物测试发现“方形导出时重新执行完整自动构图”会在部分载具上把相机错误拉远，导致整车只占输出中央很小区域。现在导出直接继承实时预览相机的位置、方向和垂直 FOV；切换为 1:1 宽高比后，仅当包围盒角点即将超出画面时才逐步后退。导出结束后恢复完整相机快照，不再再次调用通用 `fitCamera()`。

进一步实物验证表明，即使继承预览相机，OGRE模型中未实际绘制但参与几何包围盒的内容仍可能造成大面积留白。最终方案改为独立导出相机与像素级二次构图：先按预设姿态在1024–2048像素的隐藏方形画布中渲染，用专用测量背景取得真正被绘制的载具像素边界，再按留白参数等比放大、居中并高质量缩放到用户选择的输出尺寸。测量背景不会进入最终PNG，实时预览相机也不会被导出过程修改。

### 阶段 F：扩大可调 FOV 范围

第二轮实物对照反馈表明原版图标的广角透视比阶段 E 的最大 `65°` 更强。保留标准透视模型和角点拟合算法，扩大并强化用户控制：

- 最终 UI 名称统一为简洁的 `fov`；
- 垂直 FOV 范围由 `20°–65°` 扩展为 `15°–150°`；
- 新建/恢复默认设置的 FOV 由 `35°` 改为 `90°`；
- 滑块标注 `15°` 平缓、`90°` 广角、`150°` 极端；
- 参考图建议先在 `90°–120°` 范围内搜索，再配合相机方位、俯视角和留白微调；
- 已保存的旧预设继续保留其原 FOV，不强制覆盖，避免用户已有成果丢失；“恢复默认”会使用新的 `90°`。

FOV 接近 `150°` 时相机距离会非常近，但每个包围盒角点仍受同一透视不等式约束；near plane 最低限制为 `0.01`，避免相机贴近车体时错误裁切。

## 3. 完整数据流

```text
当前打开的 leaf .vehicle
          + 自动/手动 base .vehicle
          │
          ▼
composeVehicle()
          │  合成 SourceDocument（只用于预览）
          ├─ physics.visual_offset
          ├─ visual.mesh_filename / class / offset / turret_index / index
          └─ turret.weapon_key / weapon_offset / parent_turret_index
                    │
                    ▼
             ResourceCatalog.weapon()
                    │
                    ├─ model mesh_filename ──► ResourceCatalog.resolve(model)
                    └─ model filename=.xml ─► 静态体素模型
          │
          ▼
IconRenderController 组合 Object3D
          │
          ├─ 应用炮塔父链和临时局部偏移
          ├─ 应用主炮塔预览偏航
          ├─ 应用全车预览偏航
          └─ Box3 自动包围（包括炮管）
          │
          ▼
白色 Lambert 材质 + AmbientLight + DirectionalLight
          │
          ▼
MSAA WebGLRenderTarget（透明背景）
          │
          ▼
全屏 luminance threshold shader
          │
          ├─ 模型片元：#000000 或 #FFFFFF
          └─ 透明区域：预设背景，默认 #181818
          │
          ▼
实时 Canvas / 指定尺寸 PNG
```

## 4. 车辆装配规则

### 4.1 全局视觉位移

读取第一项 `physics.visual_offset`。普通视觉模型世界位置为：

```text
world = visual_offset + visual.offset + temporaryOffset
```

### 4.2 轮组视觉

`visual class="tire" index="N"` 继续使用现有 `tireVisualPosition()`：每个 `tire_set` 对应两个视觉索引，偶数位于 +X，奇数位于 -X。

### 4.3 炮塔视觉

`visual class="turret" turret_index="N"`：

```text
pose = turretWorldPose(N, parent chain, optional turretYaw delta)
world = visual_offset + pose.position + rotateY(visual.offset + temporaryOffset, pose.rotation)
object.rotation.y = pose.rotation
```

### 4.4 武器模型

每个顶层 `<turret>` 作为一个可选择的 `weapon` 部件。先由 `weapon_key` 解析 `.weapon`，再加载其中的 OGRE mesh 或静态体素模型：

```text
pose = turretWorldPose(turret index, parent chain, optional turretYaw delta)
world = visual_offset + pose.position + rotateY(weapon_offset + temporaryOffset, pose.rotation)
object.rotation.y = pose.rotation
```

静态体素武器保持现有约定：绕 Y 轴 `+90°`，并使用 `SOLDIER_GAME_SCALE = 0.04`。OGRE 武器 mesh 不额外旋转。

### 4.5 临时偏移

键格式：

```text
visual:<SourceNode.id>
weapon:<SourceNode.id>
```

值为 RWR 局部 XYZ 三元组。偏移只存在于 `IconRenderer.vue` 的响应式内存对象中：

```ts
type IconPartOffsets = Record<string, [number, number, number]>;
```

切换载具或卸载渲染标签时清空，不序列化到预设，不调用 `SourceDocument.set()`，也不调用任何载具/武器保存命令。

## 5. 相机与自动构图

相机使用 `THREE.PerspectiveCamera`，遵守标准近大远小透视。当前默认垂直视场角为 `90°`；较小视场更接近长焦、透视较平，较大视场强化近远尺寸差。可调范围为 `15°–150°`。

方位角、俯视角转换为单位方向：

```text
x = sin(azimuth) * cos(elevation)
y = sin(elevation)
z = cos(azimuth) * cos(elevation)
```

自动构图步骤：

1. 对已经应用全车偏航的 `root` 调用 `Box3.setFromObject()`；
2. 相机看向包围盒中心；
3. 将包围盒八角相对中心的向量旋转到相机局部空间；
4. 由垂直 FOV 和宽高比得到水平/垂直半视场正切；
5. 对每个角点分别求水平和垂直方向所需距离：

```text
distanceX >= localZ + abs(localX) * (1 + padding) / tan(horizontalFov / 2)
distanceY >= localZ + abs(localY) * (1 + padding) / tan(verticalFov / 2)
```

6. 取全部 `distanceX/distanceY` 最大值并增加小幅深度留白；
7. 将相机放在 `center + viewDirection * distance`，再按模型深度设置 near/far。

该计算以完整 Object3D 包围盒为输入，因此长炮管不会被裁切，同时保持正常透视。导出时临时以 1:1 宽高比重新拟合，导出结束后恢复预览尺寸和相机。

## 6. 光照与二值化

模型统一使用白色、双面 `MeshLambertMaterial`，不读取纹理。场景灯光：

- 一个白色 `AmbientLight`；
- 一个白色 `DirectionalLight`；
- 无阴影贴图、无雾、无色调映射。

方向光 target 会移动到当前载具包围盒中心，光源位置为：

```text
vehicleCenter + sphericalDirection(lightAzimuth, lightElevation) * 100
```

第一次渲染到透明中间目标。第二次全屏着色：

```glsl
float luminance = dot(source.rgb, vec3(0.2126, 0.7152, 0.0722));
vec3 binaryColor = vec3(step(threshold, luminance));
float coverage = smoothstep(0.02, 0.98, source.a);
gl_FragColor = vec4(mix(background, binaryColor, coverage), 1.0);
```

结果特性：

- 模型内部只有 `#000000` 与 `#FFFFFF`；
- 背景严格使用预设色，默认 `#181818`；
- 几何边缘利用 MSAA resolve 后的 alpha coverage 与背景混合，保留小图所需的抗锯齿灰阶；
- 阈值发生在光照之后，与“高于阈值全白、低于阈值全黑”的目标一致。

## 7. 参数预设

存储键：

```text
rwr-vehicle-studio.icon-render-presets.v1
```

它与资源路径预设、编辑器恢复快照完全分离。每个命名预设保存：

- `cameraAzimuth`
- `cameraElevation`
- `cameraFov`
- `vehicleYaw`
- `turretYaw`（当前作用于 0 号主炮塔，父子链继续正常继承）
- `lightAzimuth`
- `lightElevation`
- `ambient`
- `threshold`
- `padding`
- `outputSize`（新建/恢复默认使用 512；旧预设继续保留原尺寸）
- `background`

读取时 `normalizeIconRenderSettings()` 执行范围约束和默认回退：

- 相机/光照角度限制到 UI 有效范围，透视 FOV 限制到 `15°–150°`；
- 环境光、阈值限制到 `[0,1]`；
- 留白限制到 `[0,0.5]`；
- 输出尺寸只允许 `64/80/96/128/256/512`；
- 背景只接受六位十六进制颜色。

最近一次参数也会保存，重新进入应用后恢复。部件临时偏移故意不进入预设，因为 SourceNode id 和部件数量依赖具体载具。

## 8. GPU 资源与生命周期

- 资源并发上限为 6，与原编辑场景一致；
- mesh 和 voxel promise 按绝对路径缓存，失败会从缓存移除以允许重试；
- `BufferGeometry` 按 `meshPath:submeshIndex` 缓存；
- 所有普通 mesh 共用一个白色 Lambert 材质；
- 切换资源代次时清理 mesh/voxel/geometry 缓存；
- 切换载具时 `sceneGeneration` 使旧异步任务失效；
- `ResizeObserver` 更新 Canvas、MSAA target、透视宽高比和自动相机距离；
- 参数变化通过单次 `requestAnimationFrame` 合并，不运行永久 60 FPS 循环；
- 组件卸载时断开 observer、事件、GPU target、材质、几何和 renderer。

## 11. 后续维护注意事项

1. 不要让图标渲染器直接修改 `SourceDocument`。如未来需要保存部件修正，应新增显式“应用到载具”操作，并接入编辑器撤销/继承只读判断，而不是改变当前临时偏移语义。
2. 不要直接把编辑器 `SceneController.root` 暴露给图标渲染器。两者材质、相机、辅助对象和生命周期不同，共用场景会重新引入乘员/框线污染风险。
3. 如增加新的视觉层级规则，应先放入 `core/vehicle` 的纯函数，再同时供两个控制器调用，避免坐标算法分叉。
4. 如需阴影，应使用可控的自阴影或 AO 单独通道；直接开启大范围 shadow map 会改变参考图的二值块面且增加显存。
5. `threshold` 当前作用于 Lambert 光照结果。若改为法线点积阈值，应保留旧预设版本迁移，否则相同数值不会产生相同图像。
6. 输出边缘依赖中间目标 alpha coverage。不要在第一遍设置不透明场景背景，否则无法区分模型黑面与背景。
7. 若改变基础游戏安装位置，应在资源对话框中允许用户保留/替换该次要来源；不要把模组目录降为次要来源，否则同名改模会被原版覆盖。
8. 如未来支持批量导出，应复用同一 controller 的缓存，逐车等待 `setDocument()` 完成后导出，并用 `sceneGeneration` 防止交叉写图。

## 12. 当前限制

- 主炮塔偏航只对 0 号炮塔增加预览旋转；子炮塔通过父链自然继承，多个独立炮塔暂未提供逐炮塔角度 UI；
- 临时偏移只提供数值和步进编辑，不显示三轴 gizmo，以保证实时预览就是干净输出；
- 不做贴图透明裁剪，带有依赖 alpha 贴图的几何仍按完整 mesh 表面渲染；

### 透明背景导出与双重居中

实时预览仍使用用户选择的纯色背景，便于观察黑白二值结果；PNG 导出不再把该背景写入图片。后处理的导出分支输出 `binaryColor + geometry coverage alpha`，因此车辆上的黑色区域仍为不透明黑色，只有车辆之外的像素为透明。输出画布在缩放绘制前保持透明，不再用预览背景填充。

导出阶段先用不可出现在黑白模型中的洋红色执行隐藏测量，只截取实际绘制像素，再把该范围等比缩放并居中到最终方形画布。由此，相机透视造成的像素重心偏移不会被保留为大块单侧空白。

`tools/Install-RwrMapViewIcon.ps1` 在嵌入图集时还会再次按 alpha 大于3的可见像素求边界，忽略导出画布中的透明空白，然后按留白设置缩放并居中到128×128槽位。`mapview_vehicle_slots.json` 是该工具生成的槽位清单，不是执行脚本；其中的 `visible_source_bounds` 和 `placed_bounds` 可用于复核裁剪与居中结果。
- 不模拟履带动画、炮管后坐、骨骼蒙皮或损毁状态；
- 当前预设保存在本机 localStorage，尚未提供 JSON 文件导入/导出；
- Vite 构建仍提示主 JS chunk 大于 500 kB，这是既有 Three.js 单包体积警告，不影响功能正确性。
