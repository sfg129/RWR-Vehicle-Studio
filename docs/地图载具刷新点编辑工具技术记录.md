# 地图载具刷新点编辑工具技术记录

## 目标

地图对象模式只负责 `objects.svg` 中 `type = vehicle` 的固定载具、部署物和按阵营 tag 生成点。它不编辑建筑、道路、地形高度、地表混合图、树林或地图预览，因此不要求把 Inkscape 的完整地图制作能力搬进软件。

首个验证对象：

`D:\steam\steamapps\common\RunningWithRifles\media\packages\edelweiss\maps\edelweiss1`

## 最小读取输入

### 必需

1. 原版 `maps` 根目录及各地图子目录中的 `objects.svg`
   - 包含地图尺寸、基地范围、图层和所有 vehicle 刷新点。
   - 是地图对象编辑的唯一必需地图文件。
2. Vehicle 文件夹
   - 用于读取 vehicle key、name、tag、respawn_time 和基础继承。

### 为完整可视化和验证所需

3. 原版各地图子目录中的 `map.png`
   - 仅作为俯视背景。
   - 缺失时仍可编辑坐标，但没有地图背景。
4. 模组对应地图目录中的阵营 XML，例如 `allies.xml`、`axis.xml`
   - 用于确认地图实际加载的阵营以及它们引用的 `.resources`。
5. 模组 faction 资源文件夹
   - 用阵营 XML 中的 `<resources file="..."/>` 定位资源表。
   - 资源表中的 `<vehicle key="..."/>` 与 vehicle 的 `<tag name="..."/>` 共同决定 tag 刷新点的候选载具。

### 不需要

- 地形高度图和地表混合图
- 地图声音
- 建筑和材质贴图
- `mapview_frame.png`
- 地图批处理脚本
- Inkscape RWR 导出插件

## 最小模组输出

只编辑载具刷新点时，模组只需要新增或覆盖：

`mymod\edelweiss\maps\edelweiss1\objects.svg`

原版 `map.png`、地形、声音和材质仍从 Edelweiss 原包读取。模组不需要复制整个地图目录。

实际输出根目录由用户选择；当前工作流在 `mymod\pacific\maps` 与 `mymod\edelweiss\maps` 中维护地图覆盖，而不是写入模组 `packages` 子目录。

只有在对应内容确实发生变化时才额外携带：

- 阵营变化：对应的 `allies.xml`、`axis.xml` 等
- 地图配置变化：`map_config.xml`
- 地图预览变化：`map.png` 或阵营地图图像
- 地形变化：被修改的 `terrain5_*` 文件
- 自定义地图专属资源：实际新增的贴图、声音、projectile、vehicle 等

## 解析及保存策略

- 默认隐藏 `materials` 中的 vehicle 模板，避免把模板误当成地图刷新点。
- 直接列出 `layer.axis`、`layer.allies`、`layer.quickmatch`、`layer_invasion.*` 等实际图层，不暴露通用 SVG 图层面板。
- 读取嵌套 SVG transform，并将刷新点换算为世界坐标与角度。
- 保存采用基于源字符位置的差量替换：
  - 未修改的 SVG 内容逐字节保留；
  - 只修改 vehicle 的 key/tag 时仅更新 `<desc>`，不重写原有坐标和 transform；
  - 移动或旋转载具点时使用 `matrix(a,b,c,d,0,0)`，不能输出标准 SVG 中虽合法、但 RWR 不会正确读取的三参数 `rotate(angle cx cy)`；
  - 新增载具点必须使用包含 `spawn` 的唯一节点 ID，目前格式为 `spawn_rwrmap_<序号>`。只有 `rwrmap_<序号>` 时，即使图层、vehicle key、阵营资源和矩阵均正确，RWR 也会忽略该节点；
  - 保存旧版 Studio 产物时，会自动把 `rwrmap_<序号>` 和三参数旋转迁移为上述兼容格式；
  - 删除只移除目标 rect；
  - 新增通过复制同图层的现有刷新点产生，自动分配新 ID。
- 不使用 DOM/XML 全文重新序列化，以免制造 10 MB 级无意义差异或破坏 Inkscape 元数据。
- 用户选择原版 `maps` 根目录后，程序只扫描其直接子目录，并把含有 `.svg` 的目录按文件夹名列入地图工作区；例如 `edelweiss1`。
- 原版 maps、模组 maps、Vehicle 与 Faction 四类路径分别记忆，文件夹选择器也分别从各自当前路径打开。程序重启后会恢复工作区和模组输出授权。
- 输出前必须由用户选择一次模组 `maps` 根目录。保存 `edelweiss1` 时，若目标中没有 `edelweiss1` 子目录则自动创建。
- 地图模式只原子写入目标 `objects.svg`，不会创建 `.bak`、`.bak1`；载具和武器编辑器原有的备份规则不受影响。
- 拖动、平移和滚轮缩放合并到浏览器每个动画帧至多更新一次；一次拖动只建立一个撤销快照、只在结束时更新未保存状态。交互期间临时隐藏大量文字标签，图层计数和筛选结果使用缓存，避免大型地图反复全表扫描。

- 以原版 `maps` 根目录建立可持久恢复的地图工作区
- 点击地图文件夹名直接载入，保存时在模组 `maps` 根目录自动建立同名目录
- `map.png` 俯视背景
- 基地范围开关
- 图层独立显示/隐藏
- 按 key、tag、图层和 ID 搜索
- 醒目的刷新点图标与方向箭头
- 拖动位置
- 拖动旋转手柄
- 编辑固定 key 或阵营 tag
- 复制、删除、撤销
- 显示各阵营 tag 候选载具及 respawn_time
- 检测缺失 key/tag、无候选和多候选
- 只保存模组 `objects.svg` 覆盖文件

## RWR 兼容性实测

以 Pacific `island1` 为验证对象：

- 将已有 `m1919_hmg.vehicle` 节点替换为 `m1917_hmg.vehicle` 后，旧版 Studio 写出的三参数 `rotate` 会使替换失效；等价转换回矩阵后可正常生成。
- 复制已有节点并新增 `chi_ha_early.vehicle` 时，资源注册、阵营 default、图层和矩阵均正确，但节点 ID 为 `rwrmap_2` 时不会生成；只把 ID 改为 `spawn_rwrmap_2` 后即可生成。
- 因而替换与新增是两个独立兼容问题：前者由 transform 写法引起，后者由缺少 `spawn` 节点标记引起。
