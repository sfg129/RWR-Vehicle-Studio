# RWR Vehicle Studio 使用文档

## 1. 软件用途

RWR Vehicle Studio 用来减少“修改 `.vehicle` 数字 → 启动游戏 → 观察结果 → 退出游戏再改”的往返。软件会把载具外观、炮塔与武器、碰撞范围和乘员位置放进同一 3D 场景，并允许在右侧属性面板输入数值，或直接拖动视口中的三轴箭头修改位置。

常规“保存载具”严格限定为当前载具 XML。模型、纹理、人物模型和动画文件只读；武器文件仅在选中炮塔后，通过独立的“保存武器护盾”按钮写回其中的 `<shield>` 编辑结果。

正式版程序直接启动，不依赖额外的控制台窗口：Windows 上通过 GUI 子系统启动，macOS/Linux 上为原生应用。

## 2. 推荐导入流程

### 载具工作区

左侧顶部的“载具工作区”可以整体展开或折叠：

1. 单击“打开文件夹”，选择模组的载具目录或其共同上层目录；
2. 工作区按文件夹层级显示内容，单击目录行展开或折叠子目录；
3. 单击 `.vehicle` 文件会立即切换并载入对应载具，同时自动使用最后一次资源预设；
4. 单击其他格式的文件会提示“不是 `.vehicle` 载具文件”，不会尝试解析或修改它；
5. 若当前载具有未保存修改，切换前会要求确认。

程序会持久保存工作区根目录、工作区面板开合状态和已展开的子目录。关闭程序再启动时会自动重新加载同一路径并恢复目录树，无需再次选择。若原文件夹被移动、删除或暂时不可访问，左侧会显示错误，重新选择有效文件夹即可。目录树按需列举：只加载根目录的直接子项，展开某个目录时才读取该目录的子项，因此包含大量子目录或文件的工作区不会在打开时整树扫描。为避免误选整个磁盘，结构扫描（用于“增加空对象/加入新数值类”的候选范围）仍以 `.vehicle` 文件数上限 10000 作为保护。

### 单文件打开与资源导入

1. 单击“打开载具”，选择 `.vehicle` 文件。
2. 在自动打开的“资源文件夹”窗口中选择：
   - 模型文件夹：递归查找 `.mesh` 和模型 `.xml`；
   - 纹理文件夹：递归查找 `.png/.jpg/.jpeg/.bmp/.dds/.tga`；
   - 武器文件夹：递归查找 `.weapon`。
3. 每类资源的主文件夹下方默认显示一个可留空的“次要来源 1”。需要引用 DLC、其他原版包或多个模组时，可用 `＋` 继续增加来源，用 `−` 删除来源。检索顺序固定为主来源、次要来源 1、次要来源 2……；较高优先级已经找到同名文件后，不会被后续来源覆盖。
4. 默认使用软件内置人物模型和动画；也可分别选择自定义 XML。
5. 单击“建立索引并载入”。程序按文件名、不区分大小写匹配资源，不要求逐个选取。
6. 若左侧显示“未解析资源”，进入“文件覆盖”，逐个指定特殊文件。同名覆盖的优先级高于全部文件夹索引。

推荐把每类资源的共同上层目录选得稍宽一些，例如选择整个包的 `models`、`textures`、`weapons`。索引会递归子目录，因此也兼容大多数含多级包目录的模组。

### 资源路径预设

“资源文件夹”窗口可以把当前配置保存为命名预设。预设同时包含：

- 模型、纹理、武器的主文件夹；
- 每类资源按编号排列的全部次要来源；
- 人物模型选择（内置或自定义文件）；
- 人物动画选择（内置或自定义文件）。

从下拉框选中预设后单击“载入预设”，再单击“建立索引并载入”即可切换整套工作区。保存时使用已有的同名名称会更新该预设。程序还会记住最后一次成功应用的配置；以后打开其他载具时会自动扫描并载入这组路径，不再重复打开三个文件夹选择器。若路径已被移动或删除，程序会重新打开资源窗口供修正。

## 3. 编辑与视图

左侧按以下类别组织对象：基础/碰撞、操控、轮组、炮塔与武器、外观模型、乘员位置、其它对象。根级 `<modifier class="…" value="…"/>` 归入“基础/碰撞”，每个 modifier 独立列出并可编辑 `class` 与数值 `value`，包括 `blast_range`、`blast_damage` 及其它实际出现的 class。单击左侧对象或 3D 模型可选中对象，右侧会列出其所有现有 XML 属性；嵌套的 `<state>`、炮塔绑定和 `<part>` 属性也会显示。

选择载具工作区后，程序会扫描其中所有 `.vehicle`，归纳实际出现过的根级对象类型及每种 XML 标签使用过的属性：

- 左侧“选择对象类型 → 增加空对象”会向当前 `<vehicle>` 末尾写入新的空元素；
- 右侧“选择可加入的数值类 → 加入新数值类”会给当前对象加入候选属性，初始值为 `0`，随后可直接编辑；
- 属性行右侧的 `×` 删除该属性；底部“删除对象”删除整个当前对象；
- 新增和删除都进入撤销历史，误操作可立即按 `Ctrl+Z`；
- 基础载具继承项保持只读，不允许在稀疏覆盖文件中直接删除或添属性。

候选范围来自当前工作区真实文件，不是一份固定清单。若尚未选择工作区，已有属性仍可编辑，但对象/属性候选列表不可用。

### 武器护盾编辑

选中左侧“炮塔与武器”中的项目后，右侧会根据 `weapon_key` 打开对应 `.weapon` 的 “WEAPON SHIELDS” 区域：

- 每个 `<shield>` 独立列出 `offset` 与 `extent`，支持任意数量的多护盾结构；
- 修改数值后，若已经打开“显示护盾范围”，紫色线框会立即更新；
- “增加 shield”追加 `<shield offset="0 0 0" extent="1 1 1" />`；
- 每个 shield 右上角的 `×` 删除该项；
- 修改先保存在内存中，标题显示“未保存”，不会自动写磁盘；
- “保存武器护盾”才写回当前显示路径的 `.weapon`；“重新载入”可放弃未保存修改并恢复磁盘内容。

多护盾行为已按 `m4_m2.weapon` 的三个并列 `<shield>` 验证。若几辆载具引用同一武器文件，保存后它们都会使用该武器的新护盾配置。

修改输入框后，场景即时重建。存在位置属性的对象会出现红、绿、蓝三轴箭头，拖动结束后写回对应的三元数值。

### 炮塔旋转中点

左侧每个“炮塔与武器”对象都可以展开。选择其中的“旋转中点”后，视口会在该炮塔的逻辑旋转中心显示标记和三轴拖动器：

- 拖动中点会修改该炮塔的 `offset`；
- 为避免校准时整套炮塔在静止姿态下跳位，软件会在同一次修改中反向补偿该炮塔的视觉 `offset`、`weapon_offset`、直接子炮塔和直接附着乘员位置；
- 整次联动修改只产生一条撤销记录，可用 `Ctrl+Z` 一次撤销；
- 若中点或任一必须补偿的关联项来自只读基础载具，本次拖动会整体拒绝，不会只改一半；
- 只有选中“旋转中点”时，视口才显示“炮塔旋转预览”滑块。滑块范围为 -180° 到 180°，会连同子炮塔、武器和附着乘员一起旋转，用于检查中点是否正确，但不会写入 XML。

普通点击炮塔对象仍选择其武器位置；此时拖动修改的是 `weapon_offset`，旋转预览编辑器也会自动隐藏。

视口操作：

- 左键拖动：旋转相机；
- 右键拖动：平移；
- 滚轮：缩放；
- 单击模型：选择对应 XML 对象；
- “透视 / 顶视 / 侧视”：切换常用观察角度；
- “碰撞框”：蓝色显示 `extent/offset`，红色显示 `collision_model_extent/collision_model_pos`；
- “显示护盾范围”：读取炮塔引用 `.weapon` 内所有 `<shield offset="…" extent="…">`，以紫色线框显示其局部碰撞范围；
- “乘员”：显示或隐藏人物预览；
- “动画”：播放每个乘员位引用的动画；
- “损毁外观”：打开时只显示 `key="broken"` 的视觉模型并隐藏正常外观；关闭时只显示正常外观，二者不会重叠。

视口右上角会显示实测 FPS 和当前需要持续更新的动态乘员数量。静态乘员仍然显示，但不会计入“动态乘员”。

武器引用的静态体素模型 XML 以 **-X 为枪口前向、Y 为上下、Z 为左右**，而载具上的 OGRE 武器模型通常以 **+Z 为前向、Y 为上下、X 为左右**。静态体素武器模型在 `weapon_offset` 之后固定绕 Y 轴旋转 `+90°`，位置映射为 `(x,y,z) → (z,y,-x)`；这一符号由 Universal Carrier 的 Boys/Vickers K 实物模型确认，避免枪管朝后、枪托覆盖炮手。shield 经游戏内左右/前后位置对照使用相同的 `+90°` 水平映射，再叠加炮塔及父炮塔旋转；其 `extent` 的模型轴尺寸为 `(z,y,x)`。这些转换只影响显示，不修改 `.weapon` 或模型 XML 中保存的原始数值；`.mesh` 武器模型已经按模型坐标读取，不额外旋转。

## 4. 保存安全

“保存”覆盖本次会话实际打开的载具，“另存为”选择新路径。覆盖前会先在同目录创建 `<文件名>.bak`，再通过临时文件写入。程序只允许覆盖本次会话打开或另存过的载具路径。

武器护盾使用独立保存按钮，目标必须是现有 `.weapon` 文件。写回前同样创建 `<武器文件>.bak`，再通过临时文件替换。顶部文件状态会同时提示未保存的载具和武器数量；关闭程序时任一武器仍有未保存修改都会触发离开确认。

XML 编辑采用源文本属性补丁：未编辑的缩进、注释、元素顺序和属性文本保持不变。当前版本要求输入文件为 UTF-8；发现其他编码会拒绝打开，避免静默损坏中文注释。

## 5. RWR 坐标与层级

RWR 常见三元坐标顺序为 `X Y Z`：

- X：左右；样例注释说明“左为正”；
- Y：上下；
- Z：前后。

界面不偷偷交换轴，Three.js 场景也按相同 X/Y/Z 数值放置对象，便于数值与 XML 一一对应。

主要组合关系：

- 全局视觉位移：`physics.visual_offset`；
- 外观自身位移：`visual.offset`；
- 炮塔基点：`turret.offset`；若有 `parent_turret_index="N"`，该位移和旋转继续继承父炮塔；
- 炮塔视觉：`visual class="turret" turret_index="N"` 绑定第 N 个炮塔，并继承完整父炮塔变换；
- 武器模型：从 `turret.weapon_key` 找到 `.weapon`，既支持 `<model mesh_filename="…" texture_filename="…">` 的 OGRE 模型，也支持 `<model filename="weapon_….xml">` 的静态体素模型；其 `weapon_offset` 和护盾 `offset` 均按炮塔局部坐标显示；
- 乘员座位附着：`attached_on_turret="N"` 的值本身是从 0 开始的炮塔索引，`"0"` 表示附着到第一个炮塔；属性缺失才表示座位坐标基于载具原点；
- 乘员控制绑定：`character_slot` 内的一个或多个 `<turret index="N">` 表示该乘员控制哪些炮塔，与座位附着目标不是同一字段；
- 新式乘员状态优先使用 `<state class="idle" position="…" rotation="…" animation_key="…">`；旧式写法使用 `seat_position`，再退回 `position`。

索引均按 XML 出现顺序从 0 开始，与样例中的 `turret_index="0"`、`<turret index="0">` 一致。

例如 M10 的三名炮手均为 `attached_on_turret="0"`，所以三人的 `seat_position` 都以主炮塔为基准；其内部 `<turret index="0/1/2">` 仅分别声明控制对象。预览会先累计炮塔及 `parent_turret_index` 父链的平移/旋转，再应用座位局部位置和朝向。拖动这种乘员时，屏幕空间位移也会反变换回炮塔局部坐标后写入 XML。

对于附着乘员，炮塔的完整累计变换会同时作用于位置和朝向：先围绕炮塔中心旋转乘员的局部座位位置，再将炮塔（包括 `parent_turret_index` 父链）已经累计的 `rotation` 与乘员或 idle state 的局部 `rotation` 相加。未设置 `attached_on_turret` 的乘员仍直接使用载具空间位置和自身旋转。

## 6. 基础载具继承与覆盖

若当前 `<vehicle file="base.vehicle">` 引用了基础载具，软件会先在当前文件同目录自动寻找该文件，并将合成结果用于场景树、资源检查和三维预览：

`file="vehicle_base.vehicle"` 是 RWR 的无实际内容占位符，软件会单独忽略：不查找、不显示 BASE VEHICLE 区域，也不产生缺失或手动选择提示。大小写不同或带目录前缀但文件名仍为 `vehicle_base.vehicle` 时同样忽略。

- 当前文件中同类型、同序号的 `physics`、`control`、`tire_set`、`turret`、`visual`、`character_slot` 覆盖基础项；
- 当前文件没有覆盖的基础项继续显示；当前文件新增的项同时加入；
- `parent_turret_index="N"` 是从 0 开始的父炮塔编号，父链平移与旋转会作用到子炮塔外观、武器和附着座位；
- 左侧“BASE VEHICLE”区域显示自动匹配或手动指定的基础文件；场景树中的继承项带“基础”标记并只读；
- 同目录找不到基础文件时，左侧以红色提示并提供“手动选择”；即使已经自动找到，也始终可以手动替换；
- “打开基础”会把基础文件作为当前载具打开，以便直接编辑它。

合成只用于预览。保存时仍只写当前覆盖文件，不会把基础文件内容展开复制进去，也不会修改基础文件。

## 7. 撤销

顶部“撤销”按钮或 `Ctrl+Z` 可撤销最近一次属性输入、三轴拖动、对象/属性增删或“恢复本项”。最多保留最近 100 个当前载具编辑快照；打开另一载具或从磁盘重新载入时清空历史。保存后的撤销仍可回到保存前状态，此时载具会重新标记为有未保存修改。

## 8. 人物模型与动画

软件已内置以下只读资源，不再依赖开发电脑上的绝对路径：

- `soldier_army_normandy_ranger_1.xml`；
- `soldier_animations.xml`。

它们在资源窗口中默认显示为“内置”。“更改”可选择任意兼容的人物或动画 XML；自定义后可分别单击“恢复默认”重新选中软件内置资源。人物和动画选择也会随资源路径预设保存、载入。

人物模型包含体素、15 个骨骼粒子、17 个骨骼约束和体素绑定。预览会按乘员位的 `animation_key` 精确匹配动画注释；若使用 `animation_id`，按动画 XML 中 `<animation>` 的出现顺序从 **0** 开始计数。

实物验证：

- `animation_id="36"` → `driving car`；
- `animation_id="37"` → `travelling car, aiming`；
- `animation_key="tank mg still"` → 同名动画；
- `sdkfz251_mortar.vehicle` 的嵌套 idle 状态、炮塔附着炮手和乘客均能解析。

人物显示比例经最终校准固定为 `0.04`。该内部常量不显示在界面中，也不写入载具文件。

人物 XML 的 `r/g/b` 是线性 RGB；预览会显式转换为屏幕 sRGB，再通过专用无光照着色器直接输出。该路径绕过场景灯光、阴影、色调映射和 Three.js 隐式色彩空间处理，避免军服的低亮度色值被二次压暗成黑色。静态乘员姿势只计算一次；动态姿势以 20 Hz 更新骨骼体素，但相机仍按显示器刷新率渲染，使视角旋转保持流畅。

若 `<character_slot hiding="1">`，预览会完全隐藏对应乘员，不创建人物体素实例，也不播放或统计该乘员动画。`hiding="0"` 或未设置时正常显示。

## 9. 模型与纹理兼容性

已实现 OGRE 1.x 二进制 `.mesh` 的三角子网格、共享/独立顶点、位置、法线、第一套 UV、16/32 位索引、子网格名称与边界读取。实际用以下模型回归：

- `stuart_chassis.mesh`、`stuart_track.mesh`、`stuart_turret.mesh`；
- `sdkfz251_chassis.mesh`、`sdkfz251_track.mesh`、`heavy_mortar_base.mesh`。

PNG/JPEG/BMP 可直接贴图。DDS/TGA 会被索引和报告，但当前预览以材质占位色回退；这不会影响 XML 编辑或保存。非三角列表、骨骼蒙皮 OGRE 网格和特殊自定义顶点格式也会回退或跳过。

`visual <part>` 的纹理按子网格顺序匹配；单一 `texture_filename` 应用于全部子网格。这与 Stuart/Sdkfz251 的履带、轮组和车体样例一致。武器 XML 引用的静态体素模型采用与人物相同的已校准 `0.04` 体素比例和无光照颜色输出，但不读取人物骨骼动画；其 X 前向坐标会转换到场景 Z 前向，避免武器横置。

## 10. 已验证样例

### `stuart_base.vehicle`

验证了 4 个顶层炮塔、4 个乘员位、车体/损毁车体、炮塔、炮塔损毁件、左右履带、武器模型、PNG 纹理和旧式乘员属性。可视边界与 OGRE 模型尺寸处于同一载具单位，不需要对 `.mesh` 再乘额外全局比例。

验证了 3 个炮塔/武器、12 个外观节点、8 个乘员位、嵌套进入/离开/空闲状态、`attached_on_turret`、迫击炮与后机枪模型、复杂乘客动画和碰撞框。`visual class="tire" index="N"` 按每两个索引映射一个 `tire_set`，偶数放在 +X 侧、奇数放在 -X 侧，修正了 0/1 号轮胎误落原点的问题。实际桌面 GUI 已成功显示完整贴图载具、场景树、属性面板和三轴控件。

## 12. 故障排查

- 模型缺失：先确认模型文件夹包含对应 `.mesh`，再看是否存在同名文件冲突；冲突时用“文件覆盖”。
- 武器缺失：武器文件夹必须包含 `.weapon`，模型文件夹还要包含该武器引用的 `.mesh` 或静态体素 `.xml`。
- 有模型无贴图：确认纹理文件夹；若为 DDS/TGA，当前会使用占位色。
- 人物位置异常：确认座位使用的是 idle `position`、`seat_position` 还是旧式 `position`，并检查 `attached_on_turret` 与炮塔索引。
- 人物大小异常：显示比例已经固定为最终校准值 `0.04`；应检查人物模型本身是否采用相同体素尺度。
- 更换载具仍要求选路径：在资源窗口保存并成功应用一次预设；以后会自动使用最后配置。也可从预设下拉框载入另一套路径。
- 想撤销自定义人物文件：在人物模型或动画所在行单击“恢复默认”；这只改变预览资源，不会写入载具 XML。
- 保存前想回退：使用“恢复本项”；已保存后可用同目录 `.bak` 恢复。

## 13. 黑白图标渲染

顶部使用 `VEHICLE 编辑器 / ICON 渲染` 标签切换。图标渲染页与载具编辑器相互独立，但共用当前打开载具的合成预览和资源索引：

1. 打开 `.vehicle`，并在“资源文件夹”中配置模组模型与武器目录；
2. 程序会把 `D:\steam\steamapps\common\RunningWithRifles\media\packages\ww2_base\models` 作为低优先级基础模型来源，模组模型主目录中的同名文件仍优先；
3. 切换到 `ICON 渲染`，正常外观和武器会自动组合；乘员、所有框线、护盾和场景网格不会进入渲染；实时预览保留纯色背景，导出的 PNG 则把载具之外的区域保存为透明；
4. 调节相机方位/俯视角、FOV、车体或主炮塔偏航、光源方向、环境光、二值阈值与留白，中央结果实时刷新；FOV为垂直视场角，范围15°–150°，数值越大则近大远小越明显。原版图标可先尝试90°–120°；
5. 左栏选中外观或武器后，可输入临时 XYZ 偏移。它只影响当前图标会话，切换载具后清空，且不会写入源文件；
6. 在右栏输入名称并保存参数预设，可保存任意多组；从下拉框选择后单击“读取”恢复；
7. 选择 64–512 像素输出尺寸并单击“导出 PNG”，通过原生保存窗口写出图像。

默认输出背景为参考图使用的 `#181818`，模型内部经光照后严格分成纯黑和纯白，抗锯齿只出现在几何轮廓边缘。详细实现与维护约束见 `docs/图标渲染功能技术记录.md`。
