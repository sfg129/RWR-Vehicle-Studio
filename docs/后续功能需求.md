# 功能设计与实现记录

本文档最初用于记录后续需求。下述“乘员进入范围显示与编辑”已在 **0.4.0** 中实现；保留设计说明和验收范围，便于继续用实物载具校准。

## 乘员进入范围显示与编辑

### 目的

在维护 `<character_slot>` 时，直观看到乘员离开载具的方向及预期落脚区域，减少反复进入游戏检查乘员是否被车体、履带或其他外观模型阻挡的次数。

### 涉及的载具数据

目前兼容两种相关写法：

```xml
<character_slot ... exit_rotation="-1.57" />
```

以及乘员设置中形如：

```xml
<... class="entering" position="-0.95 0.7 0" rotation="0.0" />
```

0.4.0 采用的解释与写回规则：

- 如果 `<character_slot>` 存在 `enter_position`，它优先于角度推算：末端方框直接放在该载具空间坐标，路线方向由座位位置指向 `enter_position`；水平拖动只修改 `enter_position` 的 X/Z，并保留原 Y；
- 多状态格式同样直接使用 `<state class="entering" position="...">` 的载具空间位置，水平拖动写回该 state 的 `position`；
- `<state class="leaving">` 使用粉色人物尺寸方框显示其 `position`，并用方向箭头显示 `rotation`；粉色框可水平拖动并写回 leaving state 的 `position`；
- `<state class="idle">` 的 `position` 与 `rotation` 定义乘员在车上的实际姿态；黄色乘员位置框同时显示朝向箭头；
- 左侧乘员条目可展开：旧格式只有一个可选进出位置时显示 `position`；多状态格式分别显示 `entering`、`leaving` 与 `idle`。点击 entering/leaving 会自动显示并选中对应辅助框，点击 idle 与点击乘员父项相同；
- 普通格式直接使用 `<character_slot exit_rotation>` 作为离开方向；
- `class="entering"` 的 `rotation` 表示进入朝向，显示离开方向时加 `π`，拖动写回时执行严格的逆变换；
- 两种格式都从乘员座位的世界位置起画线，`entering.position` 不替代座位位置；
- 乘员使用 `attached_on_turret` 时，显示方向叠加对应炮塔的累计旋转，写回 XML 前再减去同一旋转；
- 如果两种角度字段都不存在，只显示已有载具内容，不自动增加字段。

两种字段不会被强制归并；拖动只修改当前乘员实际采用的 `rotation` 或 `exit_rotation`。

### 界面

- 在视口底部现有“碰撞框、乘员、动画、护盾范围、损毁外观”等选项附近增加“乘员进入范围”复选框；
- 增加独立的“显示乘员位置”复选框；启用后，无论 `hiding` 为 0 或 1，都用黄色人物尺寸方框标出座位位置；
- 增加默认启用的“外观框”开关并置于“碰撞框”之前；关闭后外观模型不再参与视口点选，也不显示其选择框，以便优先操作乘员、进出位置等辅助框；
- 默认关闭；
- 只有当前载具存在可解释的乘员进入/离开数据时才绘制；缺少字段时不擅自写入默认值。

### 可视化方式

对每个可显示的乘员：

1. 从乘员在载具内的世界位置出发；
2. 按“乘员离开载具时的方向”在水平面绘制一条线；
3. 在线条末端绘制一个人物占位方框；
4. 方框的水平占地和高度约等于当前固定人物显示比例下，一个站立人物模型占用的包围体积；
5. 水平线延伸至末端方框不再与载具当前可见外观重叠；
6. 将末端方框的底面降低到与载具可见外观底部等高的位置。

“可见外观”应遵守视口状态：正常/损毁外观二选一，隐藏外观不参与判定。碰撞框不是默认判定对象，因为需求针对人物与实际可见车体是否重叠。

### 高度与重叠判定实现建议

优先使用低频、确定性的几何包围体计算，不在每帧持续执行完整网格碰撞：

- 载入载具或切换正常/损毁外观后，缓存可见外观的世界空间包围盒或简化水平投影；
- 在离开方向上以人物方框的半宽为基准进行步进，并用包围盒/投影测试寻找第一个不重叠位置；
- 找到水平位置后，把方框底面设置为载具可见外观包围盒的最低 Y；
- 如果实际载具验证表明行走装置基准更符合游戏落脚高度，则可改用 track/tire 的已计算基准，但需对无行走装置载具保留外观包围盒回退方案；
- 只在数据、外观、炮塔姿态或用户拖拽发生变化时重算，不进入常规渲染热路径。

### 交互与写回

- 末端方框可选中和拖动；
- 只允许在水平面移动，不允许用户直接拖动其高度；
- 拖动时以乘员位置到方框水平位置的方向反算角度；
- 根据该乘员实际采用的数据，修改对应的 `rotation` 或 `exit_rotation`，不能同时写两个字段；
- 编辑必须进入现有撤销系统，支持工具栏撤销与 `Ctrl+Z`；
- 对需要反转角度或附加炮塔旋转的格式，显示变换和写回变换必须严格互逆，避免每次拖动后角度翻转；
- 保存范围仍是载具 XML，不修改人物模型、动画、模型或纹理文件。

### 验收样例

正式实现时至少选择以下类型各一个原版载具验证：

- 仅使用 `exit_rotation` 的固定车体乘员；
- 使用 `class="entering"` 数据的乘员；
- `attached_on_turret` / 炮塔子节点乘员；
- 隐藏乘员与非隐藏乘员；
- 正常外观和损毁外观底部高度不同的载具。
