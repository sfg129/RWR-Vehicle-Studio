# 技术结构与验证记录

## 结构选择

本软件在组织方式和工业风外观上参考 [sfg129/RWR-Editor-Next](https://github.com/sfg129/RWR-Editor-Next)，采用相同的“组件界面 / 平台无关核心 / 3D 编辑器 / 原生桌面边界”分层：

```text
src/
├─ components/     Vue 对话框与 3D 视口组件
├─ core/
│  ├─ ogre/        OGRE 二进制 mesh 解析
│  ├─ resources/   文件名索引和武器二次引用
│  ├─ soldier/     体素人物、骨骼绑定和动画采样
│  ├─ voxel/       武器静态体素 XML 解析
│  ├─ vehicle/     载具场景语义
│  ├─ workspace/   载具目录树展开与持久化设置
│  └─ xml/         源文本保真属性补丁
├─ editor/         Three.js 场景、拾取和 TransformControls
├─ platform/       可注入的 Tauri command 桥
└─ styles/         工业风主题
src-tauri/
├─ resources/      编译进程序的默认人物模型与动画
└─ src/lib.rs      文件对话框、递归扫描、内置资源读取、备份与受控保存
```

没有使用 Python。开发依赖是 Bun 与 Rust；正式程序把前端资源嵌入可执行文件，最终用户只需要对应平台的系统 WebView：Windows 用 WebView2、macOS 用 WKWebView、Linux 用 WebKitGTK。

Release 主程序在 Windows 上通过 Rust `windows_subsystem = "windows"` 链接为 GUI 子系统，不生成与主进程绑定的空白控制台窗口（该属性在 macOS/Linux 上无害且被忽略）；Debug 构建仍保留控制台，便于开发诊断。

## 性能取舍

- 文件夹扫描在 Rust 中递归执行，返回按小写文件名建立的哈希索引；
- OGRE 二进制解析在 TypeScript `DataView` 中完成，模型只加载一次并缓存；
- 人物体素用 `InstancedMesh`，单个乘员不是 1814 个独立 Three.js 对象；人物线性 RGB 在 CPU 端显式转换为显示 sRGB，再由专用无光照 shader 原样输出，避免 WebView/Three.js 隐式色彩空间与光照链路压黑；
- 骨骼约束、体素沿约束的位置和局部偏移在载入时预计算；动画热路径直接写实例矩阵的平移分量，不再逐体素创建向量或调用矩阵组合；
- 单帧或所有帧相同的静态姿势只计算一次；只有动态人物按 20 Hz 更新体素矩阵，相机和主渲染仍跟随显示刷新率；
- WebGL 像素比上限为 1.25，静态编辑预览关闭实时阴影；人物不参与视口拾取射线，避免开始旋转相机时检测上万体素；
- 载具 XML 不经 DOM 全量重排：数值修改按源字符跨度补丁，结构编辑也只插入或删除目标标签/属性，并在每次操作前进入保真撤销快照。
- 资源预设保存在应用本地存储，包含三类文件夹和两个人物资源选择；最后成功应用的配置会在下一辆载具打开时自动重建索引。
- 载具工作区目录树采用惰性列举：Rust 只返回根目录的直接子项，展开某个目录时才按需列出该目录的直接子项，不再整树递归扫描。工作区根路径、面板开合及展开路径集合保存在应用本地存储，启动时通过原生接口重新加载并懒加载已展开分支。
- 同一次 Rust 扫描链路会从工作区所有 `.vehicle` 归纳根级对象类型和逐标签属性集合，作为“增加空对象/加入新数值类”的可用范围；不依赖硬编码 schema。
- 选中炮塔时，武器编辑会为实际 `.weapon` 建立独立内存会话；护盾变化更新资源目录缓存并触发场景重建，但只有专用保存命令能写回武器。Rust 保存边界拒绝非 `.weapon` 目标，并在写入前创建 `.bak`。
- 基础载具通过 Rust 在当前文件同目录解析，或由用户手动指定；`vehicle-composition.ts` 生成只读合成预览并保留每个节点到当前稀疏覆盖文件的来源映射，因此继承项可显示但不会被误写入当前文件。
- `vehicle_base.vehicle` 按文件名识别为引擎占位符，在进入 Rust 路径解析前即被过滤，不创建基础载具状态或缺失提示。
- 当前文件撤销栈保存最多 100 个保真 XML 快照，属性输入、视口拖动和恢复操作统一进入历史；`Ctrl+Z` 与顶部按钮共用同一路径。
- 默认人物模型与约 5 MB 动画 XML 通过 Rust `include_str!` 编译进可执行文件，因此便携版不依赖原开发路径或额外资源目录。

## 持续集成与发布

GitHub Actions 在每次推送到 `main` 时运行：

- `ci.yml`：前端（`bun run test` + `bun run build:frontend`）在 Ubuntu 运行；Rust 后端在 Windows / Linux / macOS 三平台分别 `cargo test` 与 `cargo check`，验证原生代码可在每个平台编译并通过回归测试；
- `publish.yml`：三平台用 `tauri-action` 构建产物（Windows NSIS、macOS dmg、Linux deb/appimage），并发布到 GitHub Releases 的滚动 `nightly` 预发布条目——使用固定 `nightly` tag 每次提交覆盖刷新，不用版本 tag 触发。

二进制资源（OGRE `.mesh`、纹理）通过 base64 字符串 IPC 读取、在 JS 端 `atob` 解码；不使用 raw 字节 IPC，避免 macOS WKWebView 上 `ipc://` 自定义协议回传二进制响应体不可靠的问题。
